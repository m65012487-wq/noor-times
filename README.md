# noor-times

Официальные графики намаза духовных управлений мусульман (Россия и не только) в одном машинном формате — для приложения [Noor](https://github.com/m65012487-wq/noor).

Единого источника официального времени намаза в России нет: каждое ДУМ публикует свой график по-своему — картинкой, таблицей, вечным календарём. Формулы с ними расходятся на минуты (у ДУМ КБР — до 10 минут в июле), а мечети встают по графику. Здесь графики собираются каждый день, проверяются и выкладываются статическими JSON на GitHub Pages:

```
https://m65012487-wq.github.io/noor-times/v1/index.json
```

Формат данных — [FORMAT.md](FORMAT.md).

## Источники

| Управление | Охват | Откуда | Как читается |
|---|---|---|---|
| ДУМ КБР | вся республика, один график | картинки по месяцам на dinri-duneiri.ru | распознавание цифр по образцам; каждый день сверка с kbrdum.ru |
| ДУМ РТ | 44 города и района Татарстана | CSV на dumrt.ru | машинный формат, два года в файле |
| Муфтият РД | 22 из 28 городов и районов Дагестана | JSON на muftiyatrd.ru | вечный календарь, ручные описки чинятся (см. ниже) |
| ДУМ РФ | Москва и Московская область | картинка месяца на dumrf.ru | распознавание цифр; каждый день сверка с главной dumrf.ru |
| ДУМК (Казахстан) | 22 крупных города, радиус 60 км | api.muftyat.kz | открытый API, год целиком |
| MUIS (Сингапур) | вся страна | data.gov.sg, коллекция Muslim Prayer Timetables | открытые данные, новые годы находятся сами |

## Как это работает

- `sources/run.py` — запуск всех сборщиков. Сбой одного не мешает остальным: его прежние таблицы остаются на сайте, запуск помечается неудачным, и GitHub присылает письмо.
- `sources/common.py` — проверка таблицы перед записью: шесть времён по порядку суток, без скачков между соседними днями. Пороги скачков — по намазу; у ДУМ РТ шире, потому что в мае и августе их Фаджр и Иша по правилу переходят на летний счёт и обратно.
- `sources/digits.py` — распознавание графиков-картинок: сетка таблицы находится по линиям, цифры сличаются с образцами, вырезанными из сверенных вручную месяцев (`groundtruth/`). Месяц, где цифра прочитана неуверенно или таблица не сходится с методом управления, не публикуется.
- `.github/workflows/collect.yml` — каждый день в 05:17 по Москве: тесты, сбор, коммит изменившихся данных, выкладка на Pages.

## Качество данных

Сборщик не исправляет официальный график, если ошибка не очевидна по самому ряду. Две очевидные ошибки чинятся, и каждая правка записывается в поле `repairs` таблицы:

- **Блок дней, сдвинутый ровно на час** — след перевода часов, отменённого в 2014 году. Например, в календаре Муфтията РД для Агульского района Аср 25–31 октября стоит на час раньше соседних дней.
- **Одна–три ячейки, выбившиеся из ровного ряда**, или нечитаемые («11:5»): заменяются прямой между соседними днями.

Пункт, который и после этого не проходит проверку, не публикуется — приложение там считает методом управления. Сейчас так у шести пунктов Дагестана (Ахвахский, Буйнакск, Цумадинский, Докузпаринский, Казбековский, Тлярата): в их календарях постоянные ступени или сдвиги на два часа.

## Добавить управление

1. Описать управление и пункты в `authorities.json`.
2. Написать сборщик `sources/<имя>.py` с функцией `collect(log)`, которая пишет таблицы через `common.write_table`.
3. Подключить его в `sources/run.py` и добавить тесты.

Для графиков-картинок: перенести вручную один месяц в `groundtruth/<имя>-<год>.txt` и собрать образцы цифр `python -m sources.train <имя>`.

## Локально

```bash
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt pytest
.venv/Scripts/python -m pytest -q tests
.venv/Scripts/python -m sources.run            # все сборщики
.venv/Scripts/python -m sources.run kbr        # один
```

Графики принадлежат духовным управлениям; здесь они только переложены в машинный формат с указанием источника в каждой таблице.
