# Формат данных noor-times, версия 1

Сервер — статические файлы на GitHub Pages:

```
https://m65012487-wq.github.io/noor-times/v1/index.json
https://m65012487-wq.github.io/noor-times/v1/<authority>/<place>/<year>.json
```

Всё в UTF-8 JSON. Время всюду — местное время графика `HH:MM`, 24 часа.

## index.json

```json
{
  "v": 1,
  "generated": "2026-10-09T05:00:00Z",
  "authorities": [
    {
      "id": "ru-kbr",
      "name": "ДУМ КБР",
      "name_en": "Muftiate of Kabardino-Balkaria",
      "country": "RU",
      "regions": ["kabard", "кабард"],
      "utcOffset": 180,
      "fallback": { "kind": "dumKbr" },
      "source": "https://www.kbrdum.ru/8-grafik-namazov",
      "places": [
        {
          "id": "kbr",
          "name": "Кабардино-Балкария",
          "lat": 43.4981,
          "lng": 43.6189,
          "radiusKm": 100,
          "tables": [
            { "year": 2026, "path": "ru-kbr/kbr/2026.json", "start": "2026-01-01", "days": 365, "hash": "3f2a…" }
          ]
        }
      ]
    }
  ]
}
```

### Поля управления (authority)

| Поле | Смысл |
|---|---|
| `id` | Постоянный идентификатор: страна-регион латиницей (`ru-kbr`, `ru-tatarstan`, `ru-dagestan`, `ru-moscow`, `sg-muis`). |
| `name`, `name_en` | Название для людей. |
| `country` | ISO 3166-1 alpha-2 страны, в верхнем регистре. |
| `regions` | Части названия региона в нижнем регистре. Регион места (из геокодера или поиска города) подходит, если содержит хотя бы одну часть. Пустой список — управление на всю страну `country`. |
| `utcOffset` | Пояс графика в минутах. Если на устройстве в этот день другой пояс, строки таблиц не применяются. |
| `fallback` | Чем считать, когда таблицы на дату нет. Варианты ниже. |
| `source` | Страница, откуда берутся графики. |
| `places` | Пункты, для которых у управления есть графики. |

### Варианты fallback

| Значение | Смысл |
|---|---|
| `{ "kind": "dumKbr" }` | Формула ДУМ КБР (`src/utils/dumCalc.js` в приложении). |
| `{ "kind": "aladhan", "method": 14, "school": "hanafi" }` | Метод Aladhan с этим номером и мазхабом для Асра (`hanafi` или `shafi`). Без сети — ближайший локальный метод. |

### Поля пункта (place)

| Поле | Смысл |
|---|---|
| `id` | Латиницей, уникален внутри управления. |
| `name` | Название для людей. |
| `lat`, `lng` | Точка пункта. Внутри управления выбирается ближайший к месту пользователя пункт. |
| `radiusKm` | Охват, когда регион места неизвестен: пункт подходит, если место не дальше этого радиуса. |
| `tables` | Таблицы по годам. Для каждой: `year`, `path` (относительно `v1/`), `start` (первая дата), `days` (число строк), `hash` (SHA-1 файла таблицы, hex). Хеш меняется при любой правке. |

## Файл таблицы `<authority>/<place>/<year>.json`

Тот же формат, что у встроенных таблиц приложения (`assets/prayer-tables/*.json`).

```json
{
  "authority": "ru-kbr",
  "title": "ДУМ КБР — график намазов по КБР",
  "source": "https://dinri-duneiri.ru/azan/2026010.jpg …",
  "place": { "id": "kbr", "name": "Кабардино-Балкария", "regions": ["kabard", "кабард"],
             "lat": 43.4981, "lng": 43.6189, "radiusKm": 100 },
  "utcOffset": 180,
  "start": "2026-01-01",
  "days": ["06:08 07:38 12:20 14:31 16:41 18:21", "…"],
  "extra": { "fajrInMosque": ["06:43", "…"] }
}
```

| Поле | Смысл |
|---|---|
| `start` | Дата первой строки. Дальше строки идут подряд по дням, без пропусков. |
| `days` | Строки «Фаджр Восход Зухр Аср Магриб Иша» через один пробел. |
| `extra` | Необязательные массивы той же длины, что `days`. Сейчас один: `fajrInMosque` — время, когда утренний намаз совершают в мечетях (у ДУМ РТ оно позже начала Фаджра). |
| `place.regions` | Копия `regions` управления, чтобы таблица была самодостаточной. |

Фаджр в `days` — **начало** времени утреннего намаза. Аср — как в графике управления: его мазхаб уже учтён, настройка мазхаба в приложении к таблицам не применяется.

## Правила для приложения

1. **Управление.** Его выбирает регион места по `regions`. Если регион неизвестен — круг `radiusKm` любого пункта управления.
2. **Пункт.** Внутри управления берётся ближайший пункт.
3. **Год графика.** Строка берётся из таблицы нужного года. Если на этот год таблицы ещё нет, используется та же дата прошлогодней таблицы: расхождение не больше минуты-двух. 29 февраля в таком случае берёт 28-е. Если нет и её — `fallback`.
4. **Совместимость.** Новые поля могут появиться без смены версии; незнакомые поля надо пропускать. Несовместимые изменения — только в `v2/`.
